# Для разработчика

Всё, что нужно знать, чтобы читать код, чинить его и присылать правки.
Пользователю сюда заглядывать незачем.

---

## Как это устроено

```
источник  ──►  каталог (SQLite)  ──►  задание (текст)  ──►  Altium строит
KiCad          свой формат            build_*.txt           .SchLib/.PcbLib
EasyEDA        символ + посадка       CP1251, целые числа   своим API
архив          + 3D-модель                                  ▲
.SchLib                                                     │
                                              GostLibBuilder.pas
```

Python готовит **текстовое задание**, а библиотеки создаёт сам Altium: скрипт
`GostLibBuilder.pas` на DelphiScript читает задание и строит компоненты через
`ISch_Lib` / `IPCB_Library`.

Это не прихоть. Двоичные форматы Altium недокументированы, и любой сторонний
писатель рано или поздно ломает файл. Тут файл всегда пишет тот, кто его
понимает. Прямая двоичная запись осталась запасным путём и нужна редко.

## Формат задания

Строки `тег<TAB>поле<TAB>...`. Два жёстких правила, оба ради DelphiScript:

- **Кодировка CP1251 без BOM** — так его читает `TStringList` внутри Altium.
  Символы вне CP1251 уходят в `\uXXXX` и раскрываются функцией `Unesc`.
- **Только целые числа.** Координаты — во внутренних единицах Altium
  (1/10000 мила), углы — в десятых долях градуса. На русской Windows
  `StrToFloat` ждёт запятую и споткнулся бы на `1.27`.

Заголовок: `VER SCHLIB PCBLIB FONT INSTALL FRESH PINLOC COLGRAPH COLTEXT
COLPIN HIDECMT INTLIB LIBPKG VENDOR`.
Тело: блоки `FP…ENDFP` (`PAD`/`TRK`/`FARC`/`FTXT`/`FILL`/`BODY`) и
`COMP…ENDCOMP` (`DESIG`/`CMTPOS`/`PARAM`/`FPREF`/`PIN`/`SLINE`/`SRECT`/
`SARC`/`STEXT`).
Хвост: `END компонентов посадок`.

`FRESH 1` — библиотеки строятся с нуля (старые сохраняются как `.bak`),
поэтому пересборка идемпотентна и дублей не бывает.

### Отчёт о сборке

Скрипт по завершении пишет рядом с заданием `<задание>.done` со списком того,
что реально создал. `emit/buildreport.py` сверяет его со строками `COMP`/`FP`
самого задания. Проверяется и поле `JOB` — отчёт от другого задания
отвергается; старый `.done` удаляется **перед** запуском, чтобы прошлый успех
не выдал себя за новый.

## Грабли DelphiScript

Всё проверено на живом Altium 26.8.1. Автоматически ловится линтером:
`gostlib.bat lint`.

**Кодировка — CP1251, не UTF-8.** Altium читает `.pas` как ANSI. В
репозитории файл лежит в UTF-8 с LF (так он читается в pull request), а в
CP1251 с CRLF превращается при выкладке в рабочую папку —
`service.ensure_altium_script`.

**Имя переменной не должно начинаться с операторного слова.** `inC := False;`
компилятор читает как `in C := ...` и ругается «( expected». То же с `do`,
`mod`, `is`, `as`, `to`, `of`, `div`, `not`, `and`.

**Неизвестный член API — ошибка времени выполнения, и `Try` её не ловит.**
Значит «обернём в Try на всякий случай» не защита. Использовать можно только
те члены, что встречаются в рабочих скриптах; линтер держит белый список.

**Вложенная процедура не видит переменных объемлющей.**
`Can't access top level variable` — лечится подъёмом на верхний уровень.

**Зазоры маски и пасты — только через кеш площадки:**

```pascal
Cache := Pad.GetState_Cache;
Cache.SolderMaskExpansion := <целое>;
Cache.SolderMaskExpansionValid := eCacheManual;
Pad.SetState_Cache := Cache;
```

Прямое `Pad.SolderMaskExpansion := …` даёт `EAccessViolation` в
`ScriptingSystem.DLL`. Линтер проверяет это по имени с получателем: `Cache.…`
проходит, `Pad.…` — нет.

**Форма окна маски и пасты и флаг «паста включена» через API недоступны.**
Делаются геометрией: пасту убирают заведомо большим отрицательным зазором,
нестандартное окно рисуют заливками на слое пасты.

**Интерфейсные переменные объявляются без типа** (`Var SrvDoc;`) — связывание
позднее. **Функцию нельзя вызвать как процедуру.** **Forward-описаний нет.**

**Буферизованный лог — враг разбора падений.** Перед рискованной записью
вызывается `FlushLog`, иначе последние строки (и та самая, на которой упало)
остаются в памяти умершего процесса.

## Что ещё проверено на живом Altium

- **`PINLOC 0`**, а не 1: `ISch_Pin.Location` — это *корневой* конец вывода,
  со стороны тела. При `PINLOC 1` выводы уезжали ровно на свою длину.
- **Цвет задаётся каждому примитиву явно** — иначе Altium рисует графику
  синим, а текст бордовым.
- **После установки библиотек нужен**
  `IntegratedLibrary:RefreshInstalledLibraries`, иначе панель `Components`
  показывает состав на момент прошлой установки.
- **Признак «скрытый вывод» из KiCad не переносится** — в Altium такой вывод
  просто не рисуется, и подключиться к нему нельзя.
- **Автозапуск скрипта:** разделитель в командной строке — обычный `|`, без
  экранирования, а `subprocess.Popen` на Windows должен получить **строку**, а
  не список (список идёт через `list2cmdline`, кавычки становятся `\"`, и путь
  портится).
- **Числа в STEP от OpenCASCADE пишутся как `2.E-002`.** Выражение, требующее
  цифру после точки, откусывает «2» и теряет порядок — 0,02 мм превращаются в
  2 мм.
- **Незамкнутая ломаная в SVG — это `<polyline>`, а не `<polygon>`**: второй
  замыкается сам, и открытые скобки кварца превращаются в прямоугольники.

## Самопроверка

```bat
gostlib.bat selftest      больше 840 проверок
gostlib.bat lint          линтер скрипта для Altium
```

Проверяется всё, что можно проверить без Altium: формат задания и его полнота,
отсутствие дробных чисел, идемпотентность, согласованность тегов между
`jobcheck.SPEC` и `.pas`, скрытые и наложенные выводы, порядок выводов, секции
символа, габариты посадочных мест, фильтр переходных отверстий, разбор STEP,
цвет моделей, зазоры и паста, графика УГО, текстовое зеркало для git, доводка
ИИ-раскладки, сборка всех окон интерфейса, синтаксис и белый список API в
скрипте.

Одна проверка требует `gostlib/templates/empty.PcbLib` — пустой библиотеки,
сохранённой самим Altium. Она нужна только запасному пути прямой записи.

## Как присылать правки

- Прогоните `gostlib.bat selftest` и `gostlib.bat lint`.
- На новое поведение **добавьте проверку** в `gostlib/selftest.py` — и
  убедитесь, что она **падает на старом коде**. Проверка, которая проходит
  всегда, хуже, чем её отсутствие.
- Комментарии объясняют «почему так», а не «что делает строка». Если строка
  выглядит странно — напишите, какой симптом она лечит.
- Чистая копия проекта для выкладки собирается `python tools/make_repo.py`:
  из рабочей папки на гигабайт остаётся то, что действительно коммитится.
