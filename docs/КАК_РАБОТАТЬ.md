GostLib — как это теперь работает
=================================

Идея в одну строку: библиотеки .SchLib и .PcbLib строит САМ Altium своим
штатным API, а GostLib готовит ему задание. Никакого мастера импорта,
никакой ручной возни с файлами библиотек.


1. Один раз настроить
---------------------

1.1. Папка библиотеки. Запустить GostLib (run.bat) → «Настройки» →
     «Папка библиотеки» указать:

         D:\Github_dev\Altium\library\GOST

     Или из консоли:

         gostlib.bat config --set out_dir="D:\Github_dev\Altium\library\GOST"

1.2. Скрипт в Altium. GostLib при каждом запуске кладёт свежий скрипт в

         %LOCALAPPDATA%\GostLib\altium\GostLibBuilder.PrjScr

     Подключить его один раз:
         DXP → Preferences → Scripting System → Global Projects → Add…

     Если он уже был подключён раньше — ничего делать не надо, скрипт
     обновляется на месте.

1.3. Кнопка на панели (чтобы был «один тык»):
         DXP → Customize → вкладка Scripts → найти RunGostLib →
         перетащить на панель инструментов. Можно назначить горячую клавишу.


2. Рабочий цикл
---------------

    GostLib: «Из KiCad» → выбрать символ (посадка подставится сама)
    GostLib: F9 «Собрать в Altium»
    Altium:  кнопка GostLib на панели
    Готово — компоненты в панели Components.

Библиотека — полная проекция каталога: при каждой сборке она строится
заново по тому, что помечено «в библиотеке». Дублей не бывает.


3. Что появилось нового
-----------------------

* F9 «Собрать в Altium» — основной путь. Три старых пути (KiCad-мастер,
  EAGLE, прямая двоичная запись) убраны под кнопку «Запасные пути ▾».

* Вкладка «Посадка и 3D» — карточка посадочного места без открытия
  Altium: габарит по области установки, размер по площадкам, высота,
  число площадок (SMD / выводных / без металлизации), шаг, размеры
  площадок, диаметры отверстий, слои графики, состояние 3D-модели.

* Кнопки «Подгрузить / заменить 3D…» и «Убрать 3D». STEP кладётся как
  есть, OBJ/STL конвертируются в STEP автоматически. Модель реально
  вшивается в .PcbLib при сборке — руками добавлять больше не нужно.

* Поле «Высота» — высота корпуса, уходит в свойство Height посадки.

* Параметр Category у каждого компонента: Пассивные, Полупроводники,
  Микросхемы, Питание, Соединители, Электромеханика, Частотозадающие,
  Прочее. Плюс «ТипЭлемента» — точный тип по ГОСТ. В панели Components
  по ним удобно фильтровать и группировать.

* Консоль:
      gostlib.bat build --all              задание для Altium
      gostlib.bat convert script           то же самое
      gostlib.bat fpinfo RP2040            габариты посадочных мест
      gostlib.bat model <uid> корпус.step  подгрузить 3D
      gostlib.bat selftest                 самопроверка (328 проверок)


4. Если что-то пошло не так
---------------------------

В Altium есть три диагностические команды (DXP → Run Script →
GostLibBuilder):

    GostLibWhereIsJob     — где скрипт ищет задание
    GostLibCheckFile      — показать первые строки задания.
                            Внизу строка «Проверка кириллицы: Проверка».
                            Если там кракозябры — скажите, поправлю
                            раскодировку.
    GostLibListInstalled  — какие библиотеки подключены

Журнал каждого запуска лежит рядом с заданием:
    %LOCALAPPDATA%\GostLib\jobs\build_*.txt.log
Его же показывает кнопка «Запасные пути ▾ → Показать журнал скрипта».

На что посмотреть при первом запуске:

  1. Выводы символа. Если они уехали ровно на свою длину (300 mil) —
     значит Altium считает Location выводом у корпуса, а не электрическим
     концом. Лечится одним числом: в задании строка PINLOC 1 → 0.
     Скажите — поменяю в генераторе.

  2. 3D-модели: встали ли на место и не перевёрнуты ли. Поворот
     задаётся в карточке посадки (или через gostlib.bat model --rx 90).

  3. Привязка посадки к символу (Footprint в свойствах компонента).
     Если не привязалась — в журнале будет строка «не привязалось
     посадочное место».

Предыдущие версии библиотек скрипт сохраняет рядом как
GOST_Lib.SchLib.bak и GOST_Lib.PcbLib.bak.
