# Установка и сборка

## Готовый установщик

`GostLib-Setup-<версия>.exe` со страницы
[Releases](https://github.com/Madjogger1202/GostLib/releases). Python и
библиотеки не нужны — всё внутри.

Установщик спрашивает на первом экране, ставить **для всех** (в `Program
Files`, нужны права администратора) или **только для себя** (без прав). Делает
ярлыки и запись в «Приложения и возможности».

При удалении рабочая папка `%LOCALAPPDATA%\GostLib` **не трогается**: каталог
компонентов, настройки и резервные копии остаются на месте.

Рядом лежит `GostLib-<версия>-portable.zip` — распаковал и запустил, установка
не нужна.

---

## Из исходников

Нужен Python 3.10 или новее (проверено вплоть до 3.14).

```bat
git clone https://github.com/Madjogger1202/GostLib.git
cd GostLib
install.bat
```

`install.bat` создаёт `.venv`, ставит зависимости из `requirements.txt` и
готовит рабочую папку. Дальше запуск:

```bat
run.bat
```

или напрямую:

```bat
python -m gostlib.gui.app      окно программы
python -m gostlib.cli --help   командная строка
```

### Просмотр 3D телом

Обязательных зависимостей две — `PySide6` и `olefile`. Без них программа не
работает.

Просмотр моделей **телом** (настоящая триангуляция STEP) требует ещё двух
пакетов. Ставятся отдельно и обязательно **тем же интерпретатором, каким
запущена программа**:

```bat
gostlib.bat setup3d
```

То же самое есть кнопкой: «Запасные пути ▾ → Доставить пакеты для просмотра 3D
телом».

Без них программа работает и библиотеки собирает как обычно — модели просто
рисуются каркасом по нашему собственному разбору STEP. На то, что уезжает в
Altium, это не влияет никак.

## Своя сборка exe

```bat
build_exe.bat
```

Результат — `dist\GostLib.exe`, один самодостаточный файл. Первая сборка идёт
2–5 минут.

```
build_exe.bat --console       с консолью: видно traceback и print
build_exe.bat --clean         снести build/ и dist/ перед сборкой
build_exe.bat --slim          без 3D-пакетов: exe вдвое меньше
build_exe.bat --with-3d       не собирать, если 3D-пакетов нет
build_exe.bat --name MyApp    другое имя exe
```

### Почему exe то 47 МБ, то 90

Размер определяется **не папкой проекта, а тем, что установлено в
интерпретаторе**, которым запущена сборка.

`build_exe.bat` берёт `.venv\Scripts\python.exe`, если он есть, и системный
`python`, если нет. Из проектного окружения, где стоит только PySide6, выходит
примерно 47 МБ. Системный Python обычно несёт `trimesh`, `cascadio` и `numpy`,
и PyInstaller добросовестно упаковывает их — получается 90+ МБ.

Это не мусор: в большой сборке работает просмотр 3D телом. Нужен компактный
exe — соберите с `--slim` либо из окружения, где этих пакетов нет.

Скрипт печатает состав окружения перед сборкой, так что гадать не приходится:

```
Окружение сборки:
  интерпретатор: ...\.venv\Scripts\python.exe
  это виртуальное окружение проекта
  PySide6    225.3 МБ   обязателен
  trimesh      4.0 МБ   3D телом
  numpy       40.7 МБ   тянется за trimesh
```

### Установщик

```bat
installer\build_installer.bat
```

Соберёт `dist\GostLib.exe`, при необходимости сам поставит Inno Setup (через
`winget` или загрузкой с jrsoftware.org) и скомпилирует установщик. Если exe
старее исходников — пересоберётся автоматически. Если Inno Setup поставить не
вышло, будет собран портативный архив. Подробности — в
[`installer/README.md`](../installer/README.md).

## Если сборка ругается

**«Отказано в доступе: dist\GostLib.exe»** — файл занят, почти всегда потому,
что программа сейчас запущена. Начиная с 1.4.2 сборка справляется сама:
откладывает занятый файл в `GostLib.old-<дата>.exe` и собирает новый (Windows
разрешает переименовать работающий exe, хоть и не разрешает удалить). Если и
это не вышло — файл держит антивирус или открытый проводник. Найти, кто:

```powershell
Get-Process | ? { $_.Path -eq 'C:\...\dist\GostLib.exe' }
```

**`ModuleNotFoundError` при запуске готового exe** — модуль подгружается лениво,
и анализатор его не увидел. Добавьте в `--hidden-import` в `build_exe.py` либо
уберите из списка `EXCLUDE_QT` там же.

**exe запускается и молча закрывается** — пересоберите с `--console` и
посмотрите traceback. Плюс проверьте `%LOCALAPPDATA%\GostLib\crash.log`.

**Странные падения после правок кода** — пересоберите с `--clean`, PyInstaller
кеширует анализ.

**Антивирус удаляет свежий exe** — обычное дело для onefile-сборок. Добавьте
папку `dist` в исключения.

**Собрать exe под Windows из Linux или macOS нельзя.** PyInstaller упаковывает
тот интерпретатор, под которым запущен, а не кросс-компилирует.

## Чем exe отличается от запуска из исходников

- Python, PySide6 и зависимости внутри — на целевой машине ставить нечего.
- Запуск на 1–3 секунды дольше: onefile каждый раз распаковывается в
  `%TEMP%\_MEIxxxxxx` и удаляет папку при выходе.
- Код заморожен: правки в `gostlib\*.py` на собранный exe не влияют.
- Без `--console` окна консоли нет, `print` уходит в никуда.
- Скрипт для Altium, шаблоны и иконка вшиты в exe и распаковываются в рабочую
  папку при запуске — отдельно носить не надо.

## Куда программа кладёт файлы

Рядом с exe не пишется ничего. Всё лежит в **`%LOCALAPPDATA%\GostLib`**
(обычно `C:\Users\<имя>\AppData\Local\GostLib`):

| Путь | Что там |
|---|---|
| `settings.json` | настройки: стиль ЕСКД, шрифт, пути, тема |
| `catalog.sqlite` | каталог компонентов |
| `library\` | готовые `.SchLib` / `.PcbLib` / `.IntLib` |
| `models\` | 3D-модели |
| `cache\` | кеш скачанного из EasyEDA |
| `jobs\`, `current_job.txt` | задания для Altium, журналы и отчёты сборки |
| `backups\` | резервные копии каталога |
| `altium\GostLibBuilder.pas` | скрипт, обновляется при каждом запуске |
| `crash.log` | отчёт о падении программы |

Папку вывода библиотек можно переназначить в настройках. Перенести всё на
другую машину — скопировать папку `GostLib` целиком. Сбросить программу в
исходное состояние — удалить её.
